# Secure Communication Protocol (SCP)

![Python](https://img.shields.io/badge/Python-3.x-3776AB?logo=python&logoColor=white)
![Cryptography](https://img.shields.io/badge/Crypto-RSA--2048%20%2B%20AES--256--GCM-0F766E)
![Status](https://img.shields.io/badge/Status-Educational_Project-334155)

An educational Python project demonstrating **hybrid encryption** for messages exchanged between a TCP client and server. It combines RSA-OAEP (SHA-256) to wrap a randomly generated AES key with AES-256-GCM to encrypt and authenticate each message.

> **Educational use only.** This is not a production-ready secure messaging protocol. The server public key is transmitted without authentication, making the connection vulnerable to active man-in-the-middle attacks. Use established protocols such as TLS for real-world communications.

## Features

- RSA-2048 key pair generated by the server at startup
- Per-message random 256-bit AES key and 96-bit GCM nonce in client implementations
- RSA-OAEP with SHA-256 for AES key encapsulation
- AES-GCM authenticated message encryption
- Command-line and Tkinter GUI examples
- Standalone `SCP.py` demonstration of the cryptographic operations

## How it works

```text
Client                                Server
  | -------- TCP connection --------> |
  | <----- RSA public key ----------- |
  |                                   |
  | Generate AES-256 key + nonce      |
  | RSA-OAEP encrypt AES key          |
  | AES-GCM encrypt message           |
  |                                   |
  | -- encrypted key, nonce, data --> |
  |                                   | RSA private-key decrypt AES key
  |                                   | AES-GCM verify + decrypt message
```

## Getting started

Requires Python 3 and the `cryptography` package. Tkinter is also needed for the GUI versions and may require a separate system package on Linux.

```bash
git clone https://github.com/bsslq/Secure-Communication-Protocol.git
cd Secure-Communication-Protocol
python -m pip install -r requirements.txt
```

### Command-line demo

In one terminal:

```bash
python server.py
```

In another terminal on the same machine:

```bash
python client.py
```

### GUI demo

Run `python server_gui.py`, click **Start Server**, then run `python client_gui.py` and send a message. Run the GUI server and client as a matched pair.

### Standalone cryptography demo

```bash
python SCP.py
```

The client programs default to `127.0.0.1:4444`. The CLI server binds to `0.0.0.0:4444`; avoid exposing this educational service to untrusted networks.

## Security notes and limitations

- **No authenticated server identity:** public keys are not verified by certificates, signatures, or pinned fingerprints.
- **No forward secrecy:** compromise of the RSA private key may expose previously recorded session keys.
- **No replay protection or protocol-level session management.**
- **No robust message framing or resource limits:** the examples use simple JSON reads over TCP, which is a stream protocol.
- **GUI thread safety:** the GUI server updates Tkinter widgets from a background thread; this may fail on some systems.
- **Sensitive debug output:** server examples print the decrypted AES key and plaintext for learning purposes. Never log keys in production.
- The scripts are intentionally simple demonstrations, not audited cryptographic software.
